# Phase 3B — local source-locked equipment proposal replay

This phase connects the **existing optional real GroundingDINO inference script** to the guided equipment matrix. It does not create a different model, imply unreviewed boxes are verified, or fabricate video.

## Inputs

Use only a permitted, preloaded MP4 training-tool/workbench source with genuinely saved output from scripts/run_live_equipment.py. The saved model run must have:

- a *frozen*, complete SHA-256-pinned local model snapshot, source video hash, fixed prompts, device and thresholds;
- raw per-frame proposal boxes and scores generated by the existing GroundingDinoAdapter;
- an honest source-origin, license/use permission, privacy basis and a camera-specific reviewed ROI;
- NO reuse of the MEVA Camera Trust research recordings as electrical-tool footage.

**Source matching alone is not cryptographic proof that GroundingDINO executed, nor proof that its boxes are accurate.** The final replay UI says "operator-supplied unreviewed proposals". No precision/recall, attendance, tool absence, machine operability, work authorization or regulatory compliance is inferred from this local receipt. Release qualification still requires separately reviewed labels and held-out source clips.

## Existing files, zero upload loops

Make a private directory **outside the project**, containing exactly the already-prepared source recording named equipment.mp4 and the matching scripts/run_live_equipment.py receipt named live-proposals.json. No private MP4 or receipt belongs in GitHub or web/public. The CLI below reads the originals, checks MP4 metadata and source-to-receipt hash, then writes **only** equipment-replay.local.json into that same directory (it will not overwrite an existing manifest).

From the repo root:

    python scripts/prepare_equipment_replay.py --dir "C:\Private\KW-Equipment" --source-origin "Permitted local electrical-workshop recording" --license-basis "Explicit permission for private controlled demo" --privacy-basis "Approved non-identifying recording" --roi 0.05 0.05 0.90 0.90 --roi-basis "Reviewed for this recording and camera only"

The phrases above are illustrative, not permission granted by the project. Replace them with true source-specific evidence. The ROI example also must be replaced by source-appropriate coordinates.

Set the following variables **only** in a localhost Next.js development session:

    KAUSHALWATCH_ENV=development
    KAUSHALWATCH_LOCAL_EQUIPMENT_REPLAY=true
    KAUSHALWATCH_EQUIPMENT_REPLAY_DIR=C:\Private\KW-Equipment

Navigate to http://localhost:3000/demo/mission and select Equipment visibility. Under the role-specific proof matrix, the optional recorded equipment panel appears if the source, receipt and exact hashes validate. Jump between actual saved detector timestamps. Every rectangle has a normalized position derived from the saved original pixel coordinates. Outside a saved timestamp, boxes and counts are unavailable; there is no interpolation. The camera-blockage demo toggle withholds proposals.

The API exposes **no arbitrary file-path selector** and serves only the fixed source alias on a private, no-store, byte-range-enabled localhost endpoint. It refuses protected authentication deployments, staging, pilot, production, cross-site, remote hostname and public forwarders. The metadata response omits local paths, Drive IDs, frozen-manifest absolute locations and unreviewed labels not in the four camera-supported electrical-equipment classes. Multimeters remain officer-verification only. A failed source, invalid box, changed receipt or unsupported browser decoder suppresses overlay.

## Definition of qualification

The current phase is a **source-bound playback capability**. Phase 3B acceptance remains open until someone supplies actual authorized training-room footage, frozen model weights/manifest, independently reviewed per-class boxes and counts, on-camera ROI validation, negative/occluded samples, and work-schedule authorization. These assets are not on the accessible Drive inventory. Keep #103 and #91 OPEN.

Use evaluation/live_equipment_qualification.py on a separate held-out, licensed multi-camera manifest for count-level scoring; it will not mark synthetic fixtures qualified. Bounding-box accuracy (IoU/localization TP/FP/FN) needs an independently labelled box benchmark in addition to count-only precision/recall.
