# R12 — Recording-led controlled demo studio

## Audience and representation

**Route:** `/demo/studio` (local controlled mode only). This is a polished, reproducible *synthetic* product walkthrough, not a test of actual training-centre detection accuracy. The procedural MP4 files are checked against the versioned SHA-256 media manifest before playback; findings are generated by the fixed time-indexed scenario contract in `web/app/lib/demoStudio.ts`, not from video pixels. Copilot responses are local deterministic scripts, not Gemini responses. Chatbox entries are local to the browser tab and do not send to real contacts. This route is blocked in protected officer deployments.

Never describe the illustrative attendance or equipment counts as measured by the displayed video. Keep the discreet but clear “Simulated demo · scripted analysis” label in any publicly posted screen capture. The existing normal issue/centre/Chatbox routes use their own seeded local synthetic API fixture and do not receive cross-route messages from this standalone presentation studio.

## Start reliably on the filming laptop

From a clean current `main` checkout on Windows with Python requirements, Node and Chromium installed:

~~~powershell
git pull --ff-only origin main
cd web
npm ci
cd ..
# Only for an existing, already-seeded synthetic workspace; no deletion or reset
.\scripts\Prepare-KaushalWatch-OfflineBuild.ps1 -ApiPort 8001
.\scripts\Start-KaushalWatch-Judge.ps1 -ProductionWeb -ApiPort 8001 -WebPort 3002
~~~

Use an available pair of ports if 8001/3002 are occupied. The production build is bound to its exact Git commit and API port. The launcher refuses unknown/real case stores. For a fresh *disposable* folder only, follow the approved reset guard in `docs/redesign-release-acceptance.md`; do not reset files to make filming easier.

Open `http://127.0.0.1:3002/demo/studio`. Wait for **SHA-256 source verified** before pressing Play. Use the **Finding · 00:08** and **Review · 00:16** seek controls if a particular clip needs rapid staging. To return to a clean single scene use **Reset recorded demo**; changing scenarios keeps local state only for the current tab.

**Recording tips:** capture at 1366×768 or larger, browser zoom around 90–100%, no other apps in frame, use cursor intentionally and move between tabs slowly, keep the visible demo label, disable operating-system notification popups, and record the narration separately if the microphone causes feedback. Keep source audio muted; these clips are not actual training-centre CCTV.

## Expected deterministic progression

Every 20-second procedural recording has five fixed checkpoints at 0, 4, 8, 12 and 16 seconds. The simulated observation appears at 8 seconds; a review issue at 12 seconds; the local demo follow-up at 16 seconds. The three scenarios are:

1. Attendance: 28 reported vs 19 illustrated observed, difference 9; these numbers are **not** computed from the procedural training-bay pixels.
2. Infrastructure: 3 required training panels vs 2 illustrated visible, difference 1; **not** a verified DOD/GroundingDINO inference.
3. Camera usability: 21 reported vs **observed unknown**. Do not claim obstructed camera frames are proof of tampering or that nobody attended.

Copilot answers are explicitly source/provenance-aware and do not require network API calls. Reset and cross-scene navigation do not modify persisted officer case records or API staff data.
